# Convention Session — 2026-08-08 (2)

Focus: end-session review of the convention itself, plus constitution gaps not raised in [session-2026-08-08](session-2026-08-08.md). Constitution reviewed as of commit `a348fbb`.

## Proposed amendments (constitution)

1. **Amend Article 1/5 — Ratification is recorded.** Owner decisions on proposals (adopt or reject, with a one-line rationale) are recorded in the session file whose status changes. Today the constitution requires humans to ratify but nothing requires the ratification decision itself to be traceable. *Grounding: OECD AI Principles (accountability); consistent with prior amendment 3 (traceability).* Unanimous.
2. **Amend Article 4 — Automated review is proportional.** Automated (hook-triggered) reviews must state what changed since the last session and produce no file when nothing new emerged. Codifies the hook prompt's no-op rule, which currently exists only in the hook, not in the constitution or skill. *Grounding: NIST AI RMF (Govern — risk-proportionate processes).* Unanimous.

## Proposed improvements (convention/skill)

3. **Fix filename inconsistency.** Skill step 6 says write `session-YYYY-MM-DD.md` with no collision rule; `index.md` and the hook prompt specify the `-2`, `-3` suffix. Following the skill literally would overwrite a same-day session. Add the suffix rule to step 6. *Internal-consistency fix; no external principle needed.* Unanimous.
4. **Codify the no-op rule in the skill.** Add to step 6: "If nothing new emerged since the latest session file, write no file and say so." Currently manual sessions have no such rule and would accrete near-duplicate proposals. Unanimous.
5. **Declare the panel a prompt device.** The five personas are simulated by one model, not independent reviewers; the skill should say so plainly, and the end-session review should not be presented as independent oversight. *Grounding: NIST AI RMF (Govern — transparency about oversight limits).* Carried 5–0; policy expert notes this strengthens their prior dissent that owner-independent review cadence is still missing.
6. **Harden the enforcement hook.** A crashed review leaves the lock directory in place forever, silently disabling all future automated reviews; the log also grows unbounded. Propose a stale-lock expiry and log rotation. *Grounding: none in accepted principles — reliability argument, stated plainly.* Carried 4–1.

## Dissents

- **Security engineer** (on 6): a stale lock is an implementation bug, not a governance matter; it belongs in a repo fix, not an amendment file. Chair ruled it stays recorded here because this session cannot modify the hook and the failure mode silently defeats an adopted enforcement mechanism.
- **Product engineer** (on 1): recording rejection rationale adds ceremony for a playground repo; accepts the amendment but holds a checkbox-level record ("rejected — out of scope") must suffice.

None of the above is applied; all await owner ratification. Prior session's proposals remain pending and are not re-proposed here.
